# BB_229 使用者電腦跑瀏覽器測試：規則與操作卡（2026-11-02 10:3x，BB（帳號 A）；使用者：「這個測試是不是要寫入規則 我有空的時候可以跟你說 現在叫我電腦跑 powershell」；請 LAWWW 登記成 D123）

## 規則（永久）
1. **使用者有空時，只要說「現在可以用我的電腦跑測試」（或意思相同的話）**，BB 就回一張操作卡（下面的固定指令），並說明這一輪會跑哪幾項、大概多久。使用者不用記任何指令。
2. **CC 平常就要把 cc-local 的佇列（tools/cc_local/queue.txt）排好**，把最慢的瀏覽器測試放在最前面，佇列裡隨時至少要有一項可以跑，不能等使用者說了才開始排。CC 已經在雲端跑過的項目要從佇列拿掉，不要兩邊重複。
3. 腳本只能 push 到 `claude/cc-local`，不能碰 main、開發分支、企劃線；腳本裡不能放任何金鑰。這台電腦不跑 AI，所以**不耗用 Claude 的額度**。
4. 結果推上來以後，CC 讀結果寫初判，BB 判定 PASS／FAIL（D100、D119 不變）。
5. 腳本改了版本，就在操作卡上註明；使用者照操作卡貼就會抓到最新版，不用另外說明。
6. 這台電腦（AMD Radeon RX 6600M）跑出來的結果，標示「Windows＋GPU（Playwright 有視窗）」。**這不是 iPhone 實機**，照 TESTING.md 分清楚。

## 操作卡（使用者照貼；每一行貼完按 Enter，等出現新的 `PS ...>` 再貼下一行）
1. 打開 PowerShell，先按一次 **Ctrl + C**，把輸入列清乾淨。
2. 依序貼：
```
cd $env:USERPROFILE\Documents\Lawstudent
```
```
git fetch origin claude/cc-testing
```
```
git checkout origin/claude/cc-testing -- tools/cc_local
```
```
powershell -ExecutionPolicy Bypass -File .\tools\cc_local\run_queue.ps1
```
3. 跑的時候會跳出瀏覽器視窗，**不要按 X**；擋到的話按「－」縮小就好。
4. 畫面出現 `===== SUMMARY =====` 就是跑完了，跟 BB 說一聲。
5. 只想跑其中幾項：在最後一行後面加上 `-Only 項目代號,項目代號`（BB 會告訴你代號）。

## 11-02 11:5x 補強（使用者問「我電腦的測試跟你們的規則有一樣嚴謹嗎」）
今晚出事的都在工具，不在遊戲：quota_check 寫錯，卡了 20 分鐘；run_queue 新入口沒有實跑過就推上去；使用者貼的迴圈少一個 `}`，PowerShell 停在 `>>`，迴圈其實從沒開始過，是使用者 11:48 自己去看才補上的。補強如下：
1. **工具也要先測**：新寫或改過的探針、quota_check 這類 py 工具，要先在雲端實際跑過一次（至少 dry-run 或縮小版），才能排進 cc-local 佇列。PowerShell 腳本雲端跑不了，所以要在推上去的同時保留一個「使用者電腦實際跑過」的退回層（run_queue_proven.ps1）。
2. **貼指令要附預期畫面**：要使用者貼的指令，BB 一定附「貼完應該看到什麼」（例如提示字回到 `PS C:\...>`，或開始印 `[時間] git fetch`；停在 `>>` 就是少了括號）。
3. **「探針問題」不能直接放過**：判定為探針問題的 FAIL，修好以後一定要重跑到 PASS，才算數。
4. **發布判定要分三類**：真實玩家流程（不用捷徑）、走捷徑的探針（有【前置】）、要 iPhone 實機確認的，分開列。
5. **修改前對照**：有修 bug 的項目，佇列裡要排修改前的對照（例如 R12b），沒有對照的要註明原因。
