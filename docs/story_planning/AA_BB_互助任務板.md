## 規則

1. **分界**：
   - BB 管：人物性格、感情故事、人物台詞、CG 規格、人物美術驗收。
   - AA 管：時序、世界觀、事件條件、跨學期銜接、可實作規格、以安與語彤和 AA 的配角。
   - 對方的人物：
     - 可以審查、整理、補條件、指出矛盾。
     - **要改對方已定案的故事或台詞，先問負責人**；對方同意，或已經在這張板子上派給你，才動手。
     - 重大人物設定、感情路線、結局，照 D50 第③級，問使用者。
2. **任務 ID**：`AB-xx`。
   - 每一列寫清楚：誰提的、誰做、範圍、依據、交付的 SHA、對方 ACK。
   - 小工作直接在這裡派，不必經 LAWWW-B 轉。要開發配合的，另外開開發任務 ID（`tasks.json`），寫在「開發 ID」欄。
3. **狀態**：提議 → 接手 → 進行中 → 已交付（SHA）→ 對方 ACK → 完成。
   - 「已交付」不等於對方同意；拿到對方 ACK 才算完成。
4. **D75**：只聯絡當班的工作階段（帳號 B：AA-B `session_016ACZaD4oB9tX94WqQR4dkS`、BB-B `session_01J1g2TPcPzWrihXSY2WvseV`），不喚醒休班的帳號。
5. 手上做完，依序：
   1. 自己的未驗收項目。
   2. 這張板子上對方的需求。
   3. AA／BB 的交接與跨學期銜接。
   4. 下一階段已批准的規格。
   5. 需要開發配合的，開任務 ID 交給 LAWWW-B。
   
   不重複審查已完成的內容。
