## 測法

- 用 `tests/pg_harness.js` 載入遊戲，另外載入 `study_units.js`、`study3d.js`、`faildelay3d.js` 等。
- 每學期照 `CLS.examList` 的日期順序，呼叫**真正的** `CLS.runExam`。`G.day` 設成考試那天。
- 學期末呼叫**真正的** `CLS.showGrades`，它會用 `planRetakes` 排重修。
- 大四下的流程：
  - 6/18 呼叫**真正的** `FD.check`，排補考。
  - 6/26 呼叫**真正的** `FD.makeup`，裡面跑 `runExam` 的 makeup。
- `GM.addNote` 是從 `src/game3d.js` 抽出 `addNote` 的原始碼來執行，不是自己重寫的。
- 讀檔測試也一樣：從 `game3d.js` 抽出 `migrate`／`defaults` 來跑。
- 作答模式：

| 模式 | 怎麼答 |
|---|---|
| random | 每題隨機選，種子 1–12（另外跑過 1–50） |
| mix | 每場考試一半機率全對、一半隨機 |
| allright | 全部答對 |
| allwrong | 全部答錯：每學期都要重修，大四下要補考，補考也沒過 |
| mkpass | 大四下期末全錯，補考全對 |

- **檢查是獨立模型，不是照抄程式**：
  - 筆記數和程式自己的考試紀錄（`R.exam`）對照。
  - 內文逐題比對題庫的題幹、答案、考點。
  - miss 用另外寫的模型從作答紀錄重算，再和遊戲的 miss 比對。
- **突變測試**（證明檢查在有 bug 時會 FAIL）：故意改壞 7 種地方，每一種都被抓到。
  - M1：key 不含學期
  - M2：內文只寫第一題
  - M3：全對也寫筆記
  - M4：miss 不去重
  - M5：答錯不記 miss
  - M6：筆記插在最前面
  - M7：讀檔掉一則筆記

## 問題、觀察（不是計數錯誤，是顯示上的；判定歸 BB）

- **O1 補考的筆記標題寫「期末考訂正」**
  - 位置：`src/study3d.js:189` `S.FIX_TITLE=n=>n+'・期末考訂正'`（寫死）。
  - 補考的考卷寫「補考」（`faildelay3d.js:80` `examName:'補考'`），但筆記標題還是「海商法與海洋法・期末考訂正」。
  - 同一科大四下會有兩則同名筆記：5/30 期末、6/26 補考，只能靠日期分。
  - 重現：`node m2_notes_accum.js <資料夾>`，看 `[allwrong] 補考的訂正筆記標題` 那一行。
- **O2 重修又被當＝同名筆記重複出現**
  - 例：「刑法總則（一）（重修）・期末考訂正」在 Y1S2、Y2S1 各一則。allwrong 有 38 則標題和別則重複。
  - id 不同、內容不同，不是重複寫入，只是標題分不出來。
- **O3 筆記頁的日期沒有年份**
  - 位置：`src/social3d.js:103` 的 `dayLabel` 只回「月/日」。
  - 四年下來，「12/20」「6/8」這種日期每年都會出現，加上 O1、O2 的同名標題，要分是哪一年的考試只能看前後文。
  - 清單照時間舊→新（`game3d.js:443`），最新的考試在最下面。四年下來，上面還有自習筆記（觀念卡 252 張週卡等級的量）、課堂提問，最新的訂正要捲很久。
  - 要不要分組或倒序是設計判斷，CC 不判。
