## 0. 卡住的機制（先講清楚「卡住」在程式裡是什麼）

| 東西 | 位置 | 說明 |
|---|---|---|
| `GM.sceneBegin(opts)` | `src/game3d.js:142` | `D.busyDepth++`、`D.busyWho.push(呼叫者)`、`E.player.busy=true`、收掉路線、HUD 變透明、藏互動鍵；`opts.adv` 開 ADV。 |
| `GM.sceneEnd()` | `src/game3d.js:143` | `busyDepth--`；**歸零時**才 `player.busy=false`、HUD 回來、`E.endCinematic()`、`ADV.end()`。 |
| 搖桿、點地 | `src/engine3d.js:241`、`:248` | 只有 `!P.busy && E.cam.mode==='follow'` 才動。→ **只要有一個 sceneBegin 沒配到 sceneEnd，玩家就永遠推不動、點地沒反應、HUD 透明。** |
| 卡住偵測 `staleCheck` | `src/game3d.js:534-541` | busy 但沒有對話、選項、事件、淡出、走路超過 10 秒（只剩 ADV 開著 30 秒）→ `D.stale=true`、toast「畫面好像停住了。可以打開選單讀檔，或回標題。」、寫 `localStorage.fatiao3d_stuck`（`GM.stuckLog`）。**它只把 HUD 放回來，沒有把 `player.busy` 放開**——玩家還是走不動，只能讀檔。 |
| 讀檔解鎖 | `src/game3d.js:425`、`:433`（applySave） | `busyDepth=0`、`player.busy=false`、`endCinematic`、`chooseReset`、各模組的 `LOADLOCKS`。所以「讀檔就好了」符合使用者的描述。 |
| 互動鍵 | `src/game3d.js:247` `doInteract` | `it.onInteract(it)` **沒有 await、沒有 catch**：說話流程裡丟出的例外只會變成 unhandled rejection（console 看得到），畫面上就是停住。 |

探針判斷「沒卡住」就照這張表：`GAME.D.active===false`、`#dlg`／`#choices` 隱藏、`D.busyDepth===0`、`player.busy===false`、`ADV.active===false`、`EVENTS.running` 空、`E.cam.mode==='follow'`、`#fade` 沒有 on、手機／選單／大地圖沒開、`E.paused===false`，再實際推搖桿、點地、按 HUD。

### 5-1 手機約會的流程（照程式）
1. 手機「朋友」→ 他那一行「訊息」（`data-msg`，要有聯絡方式）→ 一對一對話串右上「約」（`data-inv`；`game3d.js:574`：`closePhone(); sceneBegin(); try{ await INV.flow(GM,id,null,false) } finally { sceneEnd() } openPhone('msg')`）。能不能約＝`friendsHTML` 的 `!INV.whyNot(G,id) && INV.hasContact && INV.canInvite`（探針的 ROSTER 用同一個判斷列名單）。
2. `INV.flow`（`invites3d.js:561`）：分類 → 地點（`menuTree`，灰掉的說原因留在同一層）→ 時間（手機沒有「現在一起過去」：今天 HH:MM、明天、其他日子）→ `INV.personal(INV.decide(...))` 的回答：
   - `accept`＝`S.accept`（state accepted）＋她的答應句；
   - `resched`（改期，`:601`）＝她給一個時間：「好，就 ○○」／「下次再說」；
   - `decline`（她沒空）、`here`（她已經在那裡，`:600`：玩家直接去，不記約）、學姊前任 S9 已讀不回、期末關係結束的拒絕（`te.refuse`）。
3. 時間快到：`INV.goPrompt`（`:379`，約定前 30 分鐘、人不在那一區）「直接過去：和○○約在…」（`goNow`→`quickGo`）／「自己走過去」；手機「今天」也有「前往」（`data-invgo`）。
