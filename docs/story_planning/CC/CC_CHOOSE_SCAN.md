### 防連點的空隙（靜態看得到的）
1. 350 ms 只擋「選單剛出現的那一下」。連點節奏比 350 ms 慢（約每秒 2～3 下），第二下之後照樣落在按鈕上。
2. 對話翻頁要兩下（第一下補完打字、第二下翻頁，`game3d.js:119`），翻頁那幾下打在畫面（`E.onTap`）上；最後一下翻完、選單出現，下一下如果晚於 350 ms 就會選到東西。
3. 自動跳出的選單（下課選單、約好時間到、開學第二天、春假揪團…，表中 ⚑）出現時玩家可能正在點地移動，點地的那一下如果晚於 350 ms 一樣會按到按鈕（選單寬 `min(400px, 100%-28px)`，直向手機幾乎整個寬度）。

## 2. 重要發現：連點會落在「從下面數第幾個」，不只是第一項

`index.html:43`：`#choices{position:absolute; right:…; bottom:calc(…+14px)}`，按鈕是直向排列、**貼著下緣往上長**。有留上一句對話時（`keep`：上一句 1.5 秒內才結束、而且不是 `opt.menu`），`renderChoose` 把選單的 `bottom` 墊高到對話框上面（`dlg.offsetHeight+22`）。所以：

- 手指不動、連點時，按到的是**從下面數第 N 個**按鈕（同時受「有沒有留對話框、對話框幾行」、「按鈕有沒有灰字 hint（變高）」影響）。
- 用這條規則重看 BUG-GOCLASS-SKIPPED-1111：起床選單（`classes3d.js:1204`）三項，「翹這堂課」是**從下面數第 2 個**；舊的翹課確認是〔翹、還是去〕，「翹」也是**從下面數第 2 個**；接著的〔再睡一下、起床〕，「再睡一下」也是從下面數第 2 個——三個選單前面都留著一句對話、高度相近，所以同一點三下＝「翹 → 再睡一下」，和使用者回報一致。新版〔還是去、翹〕讓從下面數第 2 個變成「還是去」，這一條修對了。
- 所以**「第一項不可逆」只是一半**：還要看**最下面一項、倒數第二項**，以及「下一層選單同一個位置」是什麼。表中另外標 ▼（第二項或最下面一項是 Q／$／T／P 的重大不可逆）。
- **互動鍵和選單重疊**：`#interact` 在右下（`#ctlR` bottom 12 px＋一排 44 px 小按鈕＋10 px 間距 → 約離下緣 66～114 px），選單在沒有留對話時從離下緣 28 px 往上排：最下面一顆約 28～74 px、倒數第二顆約 82～128 px。`sceneBegin` 會把互動鍵藏起來，但手指還在原地：**按互動鍵直接開的選單（表中「無對話」），第二下大概會落在倒數第二顆（部分是最下面一顆的上緣）**。這是 CSS 推算，要動態量。

## 4. 呼叫點總表（388 列）

圖例：
- **可逆（1／2）**：第一項／第二項（或最下面一項）的性質。`Q`＝重大（告白、交往或拒絕、辭職、選一個人並和其他人分開）、`$`＝花錢、`T`＝扣時間／跳時間／出門移動、`P`＝排約、送出邀約、排班、`R`＝影響關係或記憶、`F`＝記旗標或紀錄（作答、劇情分支）、`—`＝可逆（純對話、走得回來的移動）、`✕`＝取消／返回／離開。`F?`＝看資料決定、沒逐一查。
- **前一步**：`對話`＝同一個函式裡選單前最後一個 await 是一句對話（GM.say、say、S.play、sayAll…）；`選單`＝前一步就是另一個選單（中間沒有對話）；`無對話`＝同一個函式裡選單前沒有 await（多半是按互動鍵直接開；少數是呼叫端先說了話，見備註）；`自動跳出`＝時間到、站起來後由系統叫出；`呼叫端`＝包裝函式，看呼叫的人；`演出`＝前面是淡入淡出、字卡、走路。
- **標記**：★ 第一項不可逆；⛓ 接在另一個選單後面；▼ 第二項或最下面一項是 Q／$／T／P；⚑ 自動跳出（不是玩家按出來的）。
- 「第一項」「第二項」寫 `動態` 的是執行時才組出來的清單；有 `（中）`／`（最下）` 的是三項以上時另外標出的位置。
- 排序：A（第一項不可逆＋緊接對話）→ B（第一項不可逆、前面不是對話）→ C（只有後面的項目不可逆）→ D（全部可逆）；同組內依嚴重度 Q＞$＞T／P＞R＞F，再依檔名、行號。
- 「前一步」是用腳本找同一個函式裡最後一個 await（跳過 `…; return` 的提早結束分支）再人工修正，**少數可能錯**（例如呼叫端先說了話）；「可逆」是讀選了以後的十幾行程式判斷，不是跑出來的。

## 6. 可疑的發現（請 BB 判斷要不要開單）

1. **打工櫃台第一項就是「（辭職）」**（`jobs3d.js:399`）：互動鍵寫「找＜老闆＞」，玩家以為是聊天；按下去沒有對話、沒有確認，第一項就是辭職，而且依 CSS 推算正好在互動鍵的高度。比起舊 bug 更直接，連點互動鍵兩下就可能辭職。
2. **起床 bug 的同型在下課選單還在**：下課選單最下面「下一堂不去」→ 翹課確認最下面「翹」（第 5 節 #2）。這次修正把確認的「從下面數第 2 個」換成「還是去」，但「最下面」還是「翹」。
3. **選單接選單、中間沒有對話，而且同一個位置是不可逆項**：床「快轉」→「過一週」；腳踏車「買這台」→ 最後一個顏色（直接扣款）；約會「改時間」→「算了，今天不去了」；小心選擇 →「確定」；多人交往「選一個人。」→ 人名（分開其他人）。350 ms 只擋第一下，第二下以後不擋。
4. **第一項就花錢、緊接對話**：所有店家菜單（`EAT.choose` 那一族：118 巷、溫州街、水果攤、阿鳳麵店、gg2 店家、夜市、吉他店、唱片行…），事件 `ev_cafe_barista_zhiruo`（前三項都花錢）、`ev_noodle_yutong`、`ev_midnight_snack`。金額小，但「點店員對話太快＝買了東西」。118 巷「老樣子」〔好、不用〕的「好」不出菜單、直接點上次那一樣。
5. **兩項都不可逆、沒有取消**：健身房〔單次、月票〕、週日晚上〔回宿舍、住家裡〕、出遊回程〔回公館、直接回宿舍〕、研究所／國考報名〔報名、不報〕、成績〔先看、等一起看〕、Y4〔「好。」（交往）、「我們還是朋友。」〕。連點一定會選到其中一個。

## 7. 沒掃到或不確定的地方

- **全部是靜態推算**：位置重疊（第 2 節）、互動鍵高度、哪個按鈕在手指底下，都要動態量；灰字 hint 會讓按鈕變高、對話框行數會改變墊高量，實際偏移每個選單不同。
- **「前一步」欄**：腳本找同一個函式裡選單前最後一個 await（跳過 `…; return` 的提早結束），再人工修正。包裝函式（`buyFlow`、`DECIDE.choose`、`EAT.choose` 等）的「前一句」在呼叫端，已人工改成「對話」的有 15、68、180、316、377、380、382、48、64；其他「無對話」列有一部分其實是呼叫端先說了話（例如支線 `sideq3d.js` 的 step 函式、`gifthol3d.js`、`multirel3d.js:234`），沒有逐一追。
- **「可逆」欄**：讀選完以後十幾行判斷；`動態` 選項（資料決定的選單）只寫大類，沒有逐一打開資料檔（例如 `aa613_3d.js:136` 哪一項是入社、`aa720` 各事件的選項效果）。`F?` 是不確定。
- 記旗標（F）的選項很多（作答、劇情分支），照定義都算不可逆，所以 ★ 有 320 列；真正嚴重的請看 A、B 組前段（Q、$、T、P）。
- 事件引擎的 660 組只做統計和代表，沒有逐一列；其他資料檔（`VAC_DATA` 等）的 `choice` 由各自的執行檔跑，算在那些呼叫點裡。
- 沒有掃手機畫面裡的按鈕（`phone3d.js` 的「今天」可以反悔翹課、訊息回覆按鈕）、標題畫面、設定選單：它們不是 `GM.choose`，這次不在範圍。
- `character3d.js:1441／1449` 的 `choose(` 是 VRM 底模池挑模型，不是選單；`movies3d.js:57` 的 `S.choose` 是挑電影，不是選單：都已排除。
