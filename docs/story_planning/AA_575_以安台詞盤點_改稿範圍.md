## 4. 不確定的地方

1. **句數是估計**：去重會把不同條件下重複的同一句只算一次；`talkAn` 用 `GM.say(n,…)`、`honor3d` 用 `GM.say(who,…)` 這類寫法，正規式抓不到，`story3d.js` 是人工補估（~150）。`date_lines.js` 1,260 句是去重後的數字，含 32 個地點的變體，實際要審的量就是這麼多。
2. **「收鐘點費」在 src 沒有任何明文**，只有「她當家教」的設定；改成什麼（不收錢？不當家教？）會牽動第 2c 節全部，以及 `invite_replies` 的「五點有家教」「家教到七點」（AA_415 源稿）。
3. **志願表的「申請理由那一欄」**（`story3d.js:4170-4193`、`ladder.js`、`social3d.js:188`）是交換申請表的欄位，不是手帳的理由欄；要不要一起改請 AA 判斷。`sideq3d.js:160` 的「兩欄的表」不確定是不是她的手帳。
4. `heroine_asks.js`、`invites.js` 部分檔頭寫的依據（AA_494 等）我沒逐一核對是不是只對應她；`ladder.js` 她的句子分散在 `ladder_aa*.json` 八個檔，哪一句在哪一檔要看 JSON 內的 id（A-L*、A2-L*…A8-L*）。
5. 產生器的源稿在企劃線哪個 commit，以 `docs/handoff/story_import_allow.json` 列的 sha 為準（例：`ladder_aa.json`@7fca0df5、`ladder_aa_y2s1.json`@49ed7e6a、`AA_127`@482c7f6e9、`AA_202`@65239add）；改稿後白名單要更新，否則重匯會被擋。
6. 許多 tests 有逐字期望值（例：`tests/day2_whylaw_unit.js`、`termend_unit.js`、`cg_x02_unit.js`、`r2y3b_events_unit.js`、`y34b_events_unit.js`、`v6_crack_unit.js`、`date_wish_unit.js`、`msg_chat_unit.js`），改稿時要用 `apply_line_table.py --tests` 一起換。
