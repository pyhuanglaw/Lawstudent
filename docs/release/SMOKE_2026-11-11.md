### 要照實寫的幾件事

1. **「按新遊戲」不是完全照玩家的點法**。軟體算圖一秒只有幾格，Playwright 的一般點擊會等「畫面穩定」而逾時；第一次是退到直接呼叫按鈕的 `click()`、第二次是用「不等畫面穩定」的點擊才成功。按鈕本身看得到、沒有被別的東西蓋住（300×50、點得到）。在有顯示卡的電腦上應該用一般點擊再確認一次。
2. **「進得去」只代表區域建好、資源都抓到**。沒有看畫面：模型的材質、光照貼圖有沒有接上、人有沒有站對位置，這個測試都看不出來。
3. **有幾區在進去 1.5 秒後的那一刻，有 1～2 個 NPC 還是程序化的人物（不是 VRM）**：校園 1～2 個、201 教室 0～2 個、洋洋鹹酥雞 0～2 個、社科院圖書館 2F 1 個。`CHAR.failures` 是空的（不是載入失敗）。我把同樣三區（校園、教室、洋洋）對**沒打包的 repo 根目錄**和 `dist/web` 各再跑一次同樣的順序：教室都是 28 個 VRM、洋洋都沒有 NPC、校園一邊 24＋1、一邊 23＋2——**數字每次跑都會飄，跟打包無關**（看起來是「那一刻 VRM 還沒換上」）。有沒有問題請 BB 在有顯示卡的電腦上判。
4. **每一區只在「第 8 天 11:00、晴天」進去一次**，不是照劇情走進去；需要特定劇情、時段、天氣才載入的素材沒有涵蓋。
5. **對外網路**：這台機器連不到 Google Fonts，測試沒有記到字型的請求失敗（可能被瀏覽器靜靜略過）；字型在離線時的樣子沒有驗。
6. **Windows 封裝後的行為完全沒測**——還沒有封裝器；`dist/win-stage` 只驗了檔案（第 1 節）。

## 3. 沒有測的（要 BB／CC 在使用者電腦上驗的）

對應使用者規格第六節：

1. 用 `tests/deploy_check.py` 對 `dist/web` 跑一次（有顯示卡、一般點擊、它自己的區域清單與 VRM 檢查）。
2. 3D 場景、人物、室內的**畫面**：尤其光照貼圖（147 張只寫在模型檔裡的 `*_lm_day／night.webp`）有沒有接上——缺了只會變暗、不會報錯。
3. 立繪、事件 CG、電影海報**實際顯示**：開對話、看相簿、南洋戲院片單。
4. 校園、公館、溫州街、交換地圖**走路進出**（`tests/zone_transitions.py`、`tests/reachability_all.py`）。
5. 新遊戲兩條開局、存檔、讀檔、舊存檔（`tests/save_compat_v7.py`）；匯出再匯入。
6. 線上的 GitHub Pages 版：這次沒有改任何遊戲檔與部署設定，也沒有發布；下次發布照常跑發布前清單。
7. iPhone 實機。

## 5. 這次用的環境

- 雲端 Linux 容器，4 核心、沒有顯示卡；Node v22、Python 3.13；Playwright 預裝的 headless Chromium（`chromium.launch()`，不加參數；有 WebGL 2，軟體算圖）。
