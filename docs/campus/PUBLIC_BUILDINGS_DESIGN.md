## 2. 教學館模板（新模組，不改既有建築）

- **一個新模組 `src/teach3d.js`**：讀教學館的 layout JSON，建出一個多樓層區域。做法照法圖：
  - 牆、地板、樓梯、電梯、門、窗、透視、樓板；
  - 每層的導航格；
  - 備用外觀＋Blender 正式模型。
  - 普通、共同、博思各一份 layout（`src/data/putong_layout.js` 等），共用模組。既有的法律系館A、B、總圖、法圖不動。
- **房間是建築區域裡的一部分**（不是各自一個區域）。這樣才看得到學生從走廊走進教室、下課走出來，NPC 也能在房間之間走動。房間種類：
  - `lobby` 大廳（入口、公告欄、休息椅）
  - `corridor` 走廊（教室門口的等候位置）
  - `classroom` 普通教室（平面、桌椅一格一格）
  - `lecture` 大型階梯教室（照 201 的做法：一排一排的平台）
  - `study` 自習區（小桌子、插座、靠窗）
  - `lounge` 休息區
- **教室依學期載入課程**：課程資料寫教室代號（例如 `BOYA_101`、`GONGTONG_201`），教室本身不綁課程。同一間共同教學館的教室，可以連續上日文上、日文下。
- **門口上課的過渡**：室內還沒做好時，照現在的「門口上課」（2D 課堂畫面），layout 做好後換成走進教室坐下。課表資料不用改。
- **玩家自由**：沒有課、沒有劇情時，公共空間照常可以進（大廳、走廊、自習區、空教室）。進去不會自動觸發故事。教學館的開放時間沒查證前不設限。

## 3. 人流：場景隨時間改變

每個房間在某一天某一刻「應該有誰」，由下面幾項算出來。進出區域、跳過時間、讀檔都用同一套算法，結果一致：

1. **上課**：
   - 課表上在這間教室的課，包括玩家的課，以及「別的系的課」——沒寫在課表上的時段，給每間教室一個固定的「其他班級」時間表，用同一份種子產生。
   - 上課前 15 分鐘：學生陸續到走廊的等候位置、門口。
   - 開始前 5 分鐘：走進教室、坐下。
   - 上課中：坐著。
   - 下課後 0～10 分鐘：陸續起身、走出去，往出口或下一個房間。
2. **演講／活動**（博思）：
   - 活動資料寫明房間、時間、人數。
   - 公告欄提前幾天貼出來。
   - 開始前 20 分鐘：大廳、走廊有人等。
   - 開始時：大教室坐到指定人數。
   - 結束後：人潮往外走。
   - 沒有活動時，大教室只有零星自習的人，不會一直滿場。
3. **自習區**：人數照一天的時段曲線變化（早上少、下午多、考試週更多），座位照種子分配。
4. **女舍門口**：傍晚回宿舍的人、晚上在門口等人或講電話的人、深夜很少人。

**一致性規則**（使用者：「不要讓 NPC 隨玩家進出而任意生成和消失」「不要讓相同 NPC 同時出現在多個地方」）：
- 路人用「區域＋日期＋時段」當亂數種子：同一個時段出去再進來，看到的是同一批人、坐在同一些位子。
- 有名字的人只透過作息出現（`STORY.whereIs`），一個時間只會在一個地方。
- 路人沒有名字、不能是有名字的角色。
- 同一個路人模型在同一個畫面裡不重複太多：模型池輪流用，數量有上限，照畫質等級調。
- 跳過時間或讀檔後，照新的時間重算。人物的位置是「那個時間應該在的地方」，不是從上一刻慢慢走過去。

## 5. 事件介面（給 AA、BB 之後放事件資料用）

現在的條件事件已經能依學期、時間、星期、地點、旗標、記憶、關係觸發。要支援四棟建築，只**加三種條件**，觸發流程不改：
- `room`：玩家在哪一間（例如 `boya_study`、`gongtong_jp`）。房間由 layout 的範圍判斷。
- `activity`：某個活動進行中、剛結束（例如演講結束後的走廊）。
- `npcHere`：某個角色現在照作息在同一棟、同一間。

「進到某個房間時」不用新的觸發：用現有的 `trigger:'auto'` 加 `room` 條件（走進那一間就成立；配合 `once`、`cooldown_days`）。**2026-10-13 已實作**（`src/events3d.js`），測試 `tests/activities_unit.js`。

活動資料格式（`src/data/activities.js`，內容由 AA、BB 提供）：

```
{ id, title, kind:'lecture'|'club'|'exam'|…, zone, room, term:[…], weeks:[…] 或 dates:[…], weekday, t0, t1,
  poster:{ daysBefore, text }, crowd:{ n }, story:false }
```

`story:true` 的活動等使用者批准才放。系統先用測試資料驗證，**遊戲裡先不放任何活動內容**。2026-10-13 已實作 `src/data/activities.js`（清單是空的；公告欄寫「目前沒有公告的演講或活動」）。

## 6. 存檔相容

- 新欄位都是新增，舊存檔讀進來給預設值，不需要重新開始：
  - `G.activities`（看過、參加過的活動），預設空；
  - 房間是由位置算出來的，不存。
- 路人用種子重算，不存在存檔裡，存檔不會變大。
- 舊存檔的位置剛好在新建築裡（例如共同教學館那塊地本來就是一棟系館）：照現有規則，讀檔後移到最近站得住的地方（`tests/flow_teaching_buildings.py` E 段）。
- 學期代號、課程代號都是新增；改既有課程的教室（例如經濟學原理改到普通教學館），只改資料，存檔裡的上課紀錄照課程代號記，不受影響。

## 7. 效能

- 每棟建築是自己的區域，進去才載入。校園上只有外觀；正式模型壓縮（Meshopt），貼圖共用。
- 人流有上限：
  - 同一個區域同時最多約 24–40 個人，照畫質等級調；
  - 大教室滿場時，遠排的人用比較輕的模型或合併；
  - 進到教室外面時，教室裡的人照距離降級。
- 量測：校園 draw call、三角形數，放進前後比較。雲端沙盒的 SwiftShader 量不出手機實際效能，實機效能要使用者測。
