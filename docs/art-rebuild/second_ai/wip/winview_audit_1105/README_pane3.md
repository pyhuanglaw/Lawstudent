# 第三包：日和、燒臘、林家乾麵的玻璃外面接回窗景（WINVIEW-AUDIT-1105，LAWWW2-C 2026-11-05）

- 使用者 07:4x：「應該很多店面看出去的街景都不對吧，你要檢查一下。」
- 檢查表：[README.md](README.md)。前兩包：[README_gg3.md](README_gg3.md)（公館三間）、[README_wz2.md](README_wz2.md)（小路、日常失速）。
- 這一包**不用新照片**，只改程式。

## 原因

- 遊戲本來就有一套「視差窗景」（`W3.windowMat`）：
  - 照片當成窗外有景深的一面景，走動時窗框和窗外有前後關係、斜著看得到旁邊；
  - 照片是遊戲裡拍的兩層（遠景＋近景），`assets/models/env/views/<名>_{day,night}.webp`、`<名>_near_*`。
- 日和（`cvs`、從溫州街進來是 `cvs_wz`）、燒臘原址（`noodle`）、林家（`wz_lin`）都有這套照片。
- 但這三間換成正式模型（BB／AA 的 GLB）以後，程式把整個備用房間藏起來，房間的窗也跟著藏了：
  - 正式模型裡沒有窗景卡；
  - 所以玻璃外面只剩天空（室內也畫天空）。
- 燒臘（BB v7）的房間本來就沒開窗（`windows:false`）。

## 改了什麼（`src/zones3d.js`）

- `ggViewPanes(z, g0, root)`：
  - 正式模型接上以後，把房間原本的視差窗搬到正式模型的玻璃外面（往外 0.3 m）。
  - 平面放大到蓋住整面店面（林家整面開著）。中心不動＝照片的地平線不動。視差照舊，因為 windowMat 照平面上的點算，平面大小不影響照片。
  - 模型裡已經有窗景卡（名字有 VIEW）的店不動：頁間、青木、afar、Daybreak、小路、SUNNY SIDE、日常失速、2:30 AM。
  - 接在兩個地方：
    - `ggRoom` 的模型接上處（公館 AA／BB 的店；這一包是日和）；
    - `wzShop` 的模型接上處（溫州街的店；這一包是林家）。
- `shopViewPane(z, g0, o)`：沒有開窗的房間照玻璃的位置放一片。
  - 燒臘：正面玻璃（x −3～3、y 0.14～2.56、z 6.47～7.19）外面 0.1 m。
  - 用舊麵店同一個店面（公館 G00）拍的 `noodle`，地平線 2.1 m＝舊麵店的窗中心。
- 兩種窗都放進：
  - `z.wins`：房間的 applyTime 照舊換白天／晚上、照時段調色、黃昏慢慢換夜景；
  - `z.winParts`：鏡頭跑到店門外時跟著前牆藏，不然會擋住鏡頭。正式模型載入時 `attachRoomGLB` 會重設 winParts，所以在它後面加。
