# bake_room.py：隔間牆（extras.partition）兩面都烘（LAWWW2-B 2026-11-08）

**狀態：交件**。只是烘焙工具，不影響遊戲、不用換任何資產。之後在開發分支重烘有隔間牆的房間時才需要。

## 問題
- `hidden_faces()` 把牆（`WALL_`，有 `dir`）背對室內的面當成看不到：不分光照像素，整面收到同一個物件最大那一面的中心，讀同一個值。
- 隔間牆兩面都在室內，兩面都看得到。遊戲的 fadeWalls 也是照兩邊判斷；`dir` 只是淡出用的方向。
- 結果：背面整片一個亮度，沒有明暗。BB-B PC GPU 看到的是霖澤 5F 研究室那面隔間牆整片泛白（借了走廊那一面中心的 0.745）。
- 我分支上的同一個修正是 `eb857ec65`。那次交的是重烘好的 GLB 和光照貼圖（LM-PARTITION-1108，`3fb01c8d6`、`c435933a6` 已整合），工具沒有一起交。

## 修法：`bake_room_partition_1108.patch`
- 三行：`hidden_faces()` 讀完 `dir` 以後，物件有自訂屬性 `partition` 就把 `dv` 設成 None（背面不算看不到）。
- 其他判斷照舊：地板朝下、天花板朝上、`lmhide`。
- 沒有 `partition` 的牆照舊，其他房間的結果不變。
- 對開發最新 `54d2f43d3` `git apply --check` 過（`9c94d128a` 也是同一份 bake_room.py）。
- 套了以後和我分支的 bake_room.py 這一段完全一樣。

## 測試
- 輸入：總圖 B1 4.1 版原檔（blob `87f1da5e`），1024 貼圖。
- 指令：`--uvonly`（只排 UV、不烘焙，幾十秒），再用 `lm_partition_check.py`（`eb857ec65` 加的，我分支上）量隔間牆有沒有被壓成一點。

| | 看不到的面 | 隔間牆被壓成一點 |
|---|---|---|
| 開發原樣 | 90 | **292.1 m²**（28 個節點：WALL_P1～P17） |
| 套 patch | 10 | **0 m²** |
