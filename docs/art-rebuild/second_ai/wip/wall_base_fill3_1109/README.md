## 原因（從模型和光照貼圖直接量）

1. **地板在落地櫃底下，工具沒算進「被蓋住」**。和牆一起淡出的落地家具底下，地板的光照是 0：
   - 轉角唱片：唱片櫃 `WALL_left_cr_wood`（x −3.88～−3.43）。
   - 阿德：木櫃 `WALL_back_cubby_wood`、後牆販賣機 `WALL_back_ad_vc`、右牆文具架 `WALL_right_stat_rack_vcm`。

   這些櫃子沒有底面。`lm_fill_covered.py` 原本的兩條規則都抓不到：(a) 往上打線先碰到離地十幾公分的層板，超過 2 cm；(b)「在實心裡」的單雙數判斷也不成立。
2. **檢查方法本身有漏洞**。`lm_covered_fill_check.py` 用整間平均：阿德整間 0.96 倍 PASS，但木櫃底下那一群其實是 0.01 倍。八萬多格正常的格子把一塊黑的稀釋掉了。
3. **第一批的茶屋補錯檔案**（我的錯）：
   - 遊戲的一盞載入的是 `aa_support/yizhan.glb`（`WZ_SHOPS_LAYOUT.teahouse.glb`），它有自己的 `yizhan_lm_*.webp`。
   - 第一批補的 `second_ai/wz_teahouse_interior` 是已經被取代的舊檔，遊戲不載入。
   - 所以遊戲裡的茶屋一直沒補到：被蓋住的格子平均只有旁邊的 0.46 倍（白天）、0.38 倍（晚上）。
   - 例如右牆木柱和右牆一起淡出以後，後牆被柱子蓋住的那一條亮度是 0.8，接近全黑。
4. **大口 1F 的「右牆橫帶」在遊戲裡不會露出來**：dakou3d.js 一載入就把 `WALL_BANDS` 改名成 `DK_BANDS`，讓它不淡出，所以那一處不用拍。（工具不知道這個改名，照樣把它當成會淡出；那一塊第一批補過、亮度正常，沒有影響。）

## 改了什麼

1. **`tools/blender/env_second/lightbake/lm_fill_covered.py`**（LAWWW2 的工具，直接在我的分支改）：
   - 規則 (c)：朝上的面（地板）往上碰到一個「落地的」WALL_ 網格，就算被蓋住。落地的意思是它的最低點離這個面不超過 5 cm。只掛在牆上的層板、吊櫃（最低點高過地板）底下照得到光，不算。`--no-floor` 可以關掉。
   - `covered(..., info=dict)`：可以選擇多回傳每一格的世界座標、蓋住它的 WALL_、是不是只因規則 (c) 才算被蓋住（算站位用）。原本的呼叫方式和回傳值不變。
   - 補格子的步驟抽成 `fill()`：`main()` 和掃描腳本共用。在美國公寓上用 `--no-floor` 比對重構前後的輸出，兩張 webp 逐位元相同。
2. **`tests/lm_covered_fill_check.py`**（`lm_covered_fill_check_1109c.patch`，對開發分支 edaedb267）：
   - 茶屋換成遊戲真正用的 `second_ai/aa_support/yizhan`。
   - 加分群檢查：每一群（同一個表面網格、被同一個 WALL_ 蓋住）至少 100 格的，不能「不到旁邊 0.4 倍、而且暗超過 20/255」。這是看得到的黑塊；0.4～0.85 倍的牆腳漸層不算。
