## 原因
- 手機「地點」的 **「公館商圈」**（`src/data/places.js`）和公館區域的**預設落點**（`zones3d.js` 的 `zone.spawn`）都是 `(0, −30) yaw π`＝**面向校門**。
- 進區域時鏡頭在人背後（`cam.yaw = spawn.yaw + π`）→ 鏡頭在南邊 (0, 3.43, −25.5)、看北邊的校門；店（南邊騎樓，店門 z 約 21）在鏡頭後面。
- 推搖桿「往前」＝往校門走（第一步就撞到 (0, −31) 擋住的格子）；要去店裡只能拉搖桿往後。跟隨鏡頭本來就**不會跟著人轉**（只有貼著室內隔間牆時 `autoSwing` 會轉開），所以一路往鏡頭走。
- 「公館商圈」這一點也是：家裡「出門」（`home3d.js` GO_OUT）、日本那一年的出門（`jp3d.js`）、約完人放回來的地方（`arcinv3d.js` placeAfter，`arc_invites.js`、`study_slots.js` 的 `spot:"公館商圈"`）——全部經過 `PLACES.quickList()`，一起改到。
- 從校園「走出校門」的落點是另一點 `(−2.5, −29) yaw 0`（面向店、鏡頭在校門那一側），本來就對；只有「公館商圈」和預設落點是反的。

## 沒改、要 LAWWW-B 決定的（引擎的鏡頭行為，不在這個 patch）
跟隨鏡頭在**任何地方**都不會因為人往鏡頭走而轉過去（`engine3d.js` 只有拖鏡頭和貼著隔間牆的 `autoSwing` 會轉）。這個 patch 只修「落點一開始就面向反方向」。
如果還要「一直往鏡頭走 N 秒，鏡頭慢慢繞到背後」，那是全遊戲的鏡頭手感——使用者 2026-10-18 說過「轉換視角太快了……很暈」，所以我沒有做，留給 LAWWW-B／使用者決定。
