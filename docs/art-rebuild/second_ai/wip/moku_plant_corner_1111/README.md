# 木曜日二樓：衣帽架／植物縫的小孤島＋植物東南角斜推不動（MOKU-PLANT-CORNER-1111；LAWWW 11-11 14:37 派給 LAWWW2，P0）

狀態：**WORK_IN_PROGRESS**（全部 Node 測試在跑）。v9.10.25 發完 LAWWW 整合、給 BB 跑。

- patch：`moku_plant_corner_v1.patch`（3 個檔：`src/mokuyobi3d.js`、`src/engine3d.js`、新 `tests/mokuyobi_plant_corner_1111_unit.js`；基底開發分支 `566ff8b5bf`）。

## 原因（Node 掃出來的，引擎真的 NavGrid.clear＋stepEntity）

- ① 店門南邊的衣帽架 (−2.7,2.75)、落地植物 (−2.15,3.75)、樓梯間東邊隔間牆 (x −2.9)、隔間牆前的書櫃 (z 4.1～6.5) 圍出兩條比人窄的縫：植物北邊 0.45 m、植物西邊 0.4 m（人要 0.64 m）。導航格是空的、人站不進去，只有兩條縫的接角那一格 (−2.54,3.33) 剛好四點都站得住＝小孤島，16 個方向推都出不來。縫口 (−2.49,3.04) 是一條很窄的可站帶的最西端，往樓梯方向推就頂在衣帽架的角上。
- ② 引擎「站得住」只看人的前後左右四點，所以家具的外角斜對面有一小塊站得進去。站在植物東南角 (−1.82,4.00) 斜著往樓梯推（202.5°、225°、247.5°），整步、只走 x、只走 z、往左右偏 30～70° 全部還碰到植物＝一步都不動。這是所有家具外角都有的情形；木曜日這個角剛好在往樓梯的路上。
- 同一次掃描另外找到一個：西牆書櫃和 table 3 (−3,0.6) 之間、樓梯間北牆前 (−3.75,1.0) 一小塊（3 格，被桌子和牆夾住，跑步一步大時跳得進去）。

## 改法

1. `src/mokuyobi3d.js`（buildNav）：三塊補成阻擋，**只有導航，模型不動**——A 植物北邊（x −2.9～−1.9、z 2.95～3.5）、B 植物西邊（x −2.9～−2.4、z 3.45～4.1）、C (−3.75,1.0) 那一小塊（x −4.0～−3.4、z 0.95～1.1）。區域加 `z.cornerSlip=true`。
2. `src/engine3d.js`（stepEntity）新的 **cornerSlip**（**只有區域開了才用、只有玩家**；其他店完全不變）：整步、沿牆滑、半步、左右偏都動不了時，往旁邊讓開（另一軸、和推的方向相反那一邊＝離開家具）。條件：讓開 0.34／0.45／0.55 m 以後，那一軸要走得通 0.6 m（外角：沿著家具的邊過得去）；牆角（內角）讓開以後走不了幾步又撞牆，就不讓（不會被推著亂跑）。讓開的那一段走完才恢復平常的走法，接著先沿讓出來的那一軸走（`_slip`、`_slipPref`），不會一步往外一步滑回角裡。推的方向變了就取消。
   - 不想動引擎的話：只套 1 也能修 ①（小孤島、縫口）；② 要 2（測試第 3、4 項會紅）。

### CC 問的「pathTo 有路、stepEntity 卻走不出去」
