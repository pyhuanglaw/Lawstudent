# CAM-TEAYARD-1109 第二輪：一盞前院鏡頭轉到 180°，緣側屋簷擋住頭

狀態：`READY_FOR_REVIEW`（交 LAWWW-B 整合；遊戲內畫面等 CC 重拍、BB-B 判）。LAWWW2-B，2026-11-09。

## 問題

BB-B 11-09 23:23 的雲端判定（cc-testing 02566232ab，`CAM_TEAYARD_cloud_1109/`）：
- 270° PASS。
- **180° PARTIAL**：鏡頭沒有跑進牆裡，但緣側屋簷的橫樑和椽子蓋住畫面上方 45%，人物的頭和肩膀被樑擋住。CC 的鏡頭在 (−3, 2.71, 5.29)，到頭 4.08 m。

## 原因

1. **第一輪的測試用錯了俯角**。
   - 引擎在室內區域的預設俯角是 **0.38**（`engine3d.js`：`cam.pitch=E.indoor?0.38:0.22`），一盞是室內區域。
   - 第一輪的 Node 測試用的是戶外的 0.22，算出的鏡頭比較低，視線從樑下面過去，所以沒抓到。
   - 用 0.38、距離 4（這一區的 camDist）重算，鏡頭正好落在 (−3, 2.71, 5.29)，和 CC 一樣：到頭和肩膀的視線在離鏡頭 0.83 m 處被 `wzy_wood_yard_eave` 擋住，畫面有 67% 是比人物還近的屋簷。
2. **鏡頭其實在屋簷的體積裡面**。屋簷 `YARD_EAVE` 的範圍是 z 4.94～6.93、高 2.16～3.04。
3. **試過的另一個做法：把屋簷加進鏡頭碰撞**。鏡頭被擠到屋簷正下方，150°～210° 畫面上半有 46～82% 是簷下板和排水溝，比原本好不了多少，所以不用。

## 改法（`src/zones3d.js` 的 teaYard，2 處）

- 前院模型載入時記下屋簷外緣的世界座標 z（6.93）。g0 整組往 +z 移了 cz，要先更新矩陣再算，不然會少 2.3 m。
- teaYard 的 `fadeWalls`：玩家在前院、鏡頭在屋簷外緣的房子那一側時，**屋簷整組 `YARD_EAVE` 藏起來**。道理和牆淡出一樣，鏡頭在屋簷底下時屋簷不畫。
  - 加了 ±0.1 m 的緩衝，鏡頭在邊界附近不會來回閃。
  - 鏡頭在前院那一側（例如 0°，從前院看房子）時，屋簷照舊看得到。
- 主屋屋頂 `YARD_ROOF`、鏡頭碰撞都沒動。第一輪加進去的緣側牆、鄰居房子照舊。
