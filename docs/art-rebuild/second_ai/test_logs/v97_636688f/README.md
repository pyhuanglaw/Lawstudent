## flow_typhoon 分析（06:25Z，第一版，還在查）

這支測試在 636688f 是新寫的、之前沒在瀏覽器跑過（commit 訊息寫「還沒跑」）。11 項 FAIL 看起來是**三個原因連鎖**，不是 11 個獨立的問題：

1. **A（前一晚的手機）：點 `#btnPhone` 手機沒打開**（截圖 `flow_typhoon_01_A_notice.webp`、`02_A_group.webp`：右上角手機按鈕有未讀「5」，畫面還是 3D 場景；21:32 → 21:33 遊戲時間有走，所以手機面板也沒有「打開又被蓋住」——打開時 `E.paused=true`，時間會停）。
   「通知」「麵店團」「貼圖」三項都是因為手機沒打開，**遊戲本身有沒有排出這些訊息還不知道**（未讀數字 5 表示有東西進來）。
   原因還沒找到：`#toast`、`#fade`、`#caption` 的 CSS 都是 `pointer-events:none`（或只在 `.on` 時擋）；同一個 `L.tap('#btnPhone')` 其他測試也在用。要開瀏覽器查（`elementFromPoint`、點之前和點之後的 `phoneOpen`），為了不干擾候選 13 的回歸，等那兩項跑完再查。
2. **B（睡到颱風假早上）：睡覺花的時間比測試等的 90 秒長**。測試在 90 秒內一直看到第 26 天 21:35（時間停在 21.595，睡覺的過場還在跑），所以「醒來、下雨」判 FAIL；但截圖 `03_B_morning_phone.webp` 是**第 27 天週一 07:30、雨天圖示、目標「今天放假（颱風假），沒有課。自由活動：…」**——遊戲看起來是對的，是測試等太短。「今天」分頁那一項又是手機沒打開（同 1）。
3. **C（泡麵之夜）：B 的睡覺流程還沒跑完，測試就讀了 C 的存檔**。`sleepNow` 最後的「舊存檔補可昕的第一則訊息」（`story3d.js:652`，`if(!F.KX_FIRST_MSG&&F.dating_kexin)`；`F` 是 B 那份存檔的旗標，測試的 FLAGS 沒有 `KX_FIRST_MSG`）在 C 讀檔之後才輪到，結果在 C 的 17:56 演出「經濟系的那一年，你不是一個人過的。」→ 可昕（手機）「早安。今天的假設題。」（截圖 `04_C_cg_portrait.webp`）。
   這段過場占住了 18:00，泡麵之夜沒有開始；測試照自己的流程點對話、選第三個選項，選到的是可昕的「讀到一半，在想妳。」，最後停在可昕的「去上課吧。下課再跟我說你讀到哪了。」——後面 5 項 FAIL 都是這個連鎖。

### 建議（測試本身的修正，給 LAWWW 決定；我不改 tests/ 以外的檔案）

- FLAGS 加 `'KX_FIRST_MSG': True`（第 26、27 天的存檔不該再補第一天的訊息；也可以順便加 `FAM_GROUP_SENT`）。
- B：等「第 27 天、宿舍、早上」最多 90 秒太短（SwiftShader）；改成等到 `day==27` 再 `advance_dialogs` 到可以走動，而且**C 讀檔之前確定 B 的流程跑完**（`not busy and not dlg`）。
- 手機打不開的原因查到之後再附 patch（如果是遊戲的問題，會寫重現步驟給你）。
