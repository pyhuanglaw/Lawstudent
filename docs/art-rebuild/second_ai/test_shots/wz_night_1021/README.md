# PERF-WZ-NIGHT-1021：溫州街 19:30「變重」查原因

LAWWW2-C，2026-10-21。
- 起因：LAWWW-C 08:02Z 轉 BB-C 的量測（BB_218 最後一節，`perf_probe.py`）。
  - 修正前 `1a76148e` → 修正後 `43d0836f`，溫州街 19:30：
    - draw call 331 → 346（+5%）；
    - 三角形 37.1 萬 → 51.0 萬（+37%）。
  - 要我判斷是哪一批東西晚上才多出來的。
- 環境：Playwright 手機模擬（橫向）、SwiftShader；不是 iPhone 實機，數字只能互相比。

## 結論
- **沒有晚上才多出來的場景物件**。兩個版本的溫州街場景（建築、公園、道具、日式宿舍、樹、機車），晚上一模一樣。
- BB 量到的差別來自**人**（路人、騎車的人）和**陰影那一輪有沒有算進去**：
  1. 人：兩個版本都是同樣 6 個路人、2 個騎車的人，三角形也一樣，只是**位置不同**。
     - 一個人約 2.5～3.6 萬三角形；
     - 走到鏡頭前面的人多一兩個，就差 5～10 萬。
  2. 陰影：`43d0836f` 起（X79）晚上的陰影貼圖 2 秒才重畫一次。
     - BB 的工具取「等 4 秒後那一格」的 `renderer.info`：有時候是重畫的那一格（多約 71 次 draw call、8 萬三角形），有時候不是。
     - `1a76148e` 每一格都重畫。
- 所以這次沒有要修的場景物件。

## 量法與數字
- 照 BB 的 `perf_probe.py`：
  - 讀使用者 9/25 存檔（`tests/repro_1020/user_save_day9.json`），標題「讀取」；
  - [捷徑] 時間設 19:30、`GAME.enter('wenzhou')`，等 8 秒；
  - 鏡頭四個方向各量一次。

- `1a76148e` 和 `43d0836f`：draw call 完全一樣，三角形差 0.4% 以內（行道樹的遠近版本）。
- 加上 #47 的光暈合批（`gg_drawcall_atlas_glow.diff`）：
  - 溫州街 56 個光暈變一次 draw call；
  - 往 Café 那個方向少 50 次。

### 2. 照 BB 的量法、人不藏（`wz_night_cats.py`，分類）
| | `1a76148e` | `43d0836f` |
|---|---|---|
| 四個方向最多的 draw call | 325 | 310 |
| 四個方向最多的三角形 | 448,847 | 446,383 |
| 場景各模型（溫州街 GLB、公園、道具、日式宿舍、樹） | 一樣 | 一樣 |

- 這一次量 `43d0836f` 沒有比較重：BB 那一次剛好有人走到鏡頭前面，或剛好是陰影重畫的那一格。

## 建議（給 BB、LAWWW-C）
- 比場景效能時：
  - 把人藏起來（`E.npcs`、`E.extras` 移出場景）；
  - 陰影那一輪固定算進去：`renderer.shadowMap.needsUpdate=true` 再 `E.render()`。
- 要量「玩家實際看到的」：多取幾格平均，並分開記「陰影重畫的那一格」和「平常的一格」，像 `tests/perf_scenes.py` 的 `night` 那一段。
