## 原因（三個）

1. **已經載過的正式模型，淡入時才接上**：`GAME.enter` 在黑畫面建區域、畫第一格；區域裡的 `ASSETS.loadOne(key).then(attach)` 就算模型已經在快取裡，`.then` 也要等到 `await fade(false)`（開始淡入）才跑。所以淡入那幾格才編新材質的 shader、把貼圖傳上 GPU——畫面停在半淡入的地方。
2. **第一次去的地方，模型淡入以後才到**：建築模型是 `lazy`（進區域才載）。溫州街六個建築模型共約 18 MB，淡入以後 5～13 秒才一個一個到，每到一個停一下。
3. **路人底模池每次換區域輪換 8 個新的 VRM**（`src/character3d.js` 的 `C.anonPool.refresh`，使用者 10-17 P0「長得很像的路人太多」）：上一區的 8 個放掉、下載 8 個新的，到了一起換上（`upgradeModels`）。第二次進溫州街淡入後 8.5 秒那一格就是這個。**這是 LAWWW 的範圍**，下面只寫量測和建議。

另外兩件小事：

- `wz_jphouse.glb`（日式宿舍）為了燈籠、木牌，整包帶了一張 2048² 的招牌圖集；`wenzhou_street.glb` 已經有同一張。進溫州街要解碼、上傳兩份。
- 溫州街有三個藏起來的套件零件（`wzProp` 群組裡 (47.7, 7.6) 的桿子與托架），material 是 TK 的 paint 描述、不是 `THREE.Material`。平常不畫它們沒事，但 three.js 的 `compile` 會走到藏起來的物件，一碰就丟例外——prewarm 第一版在遊戲裡就是這樣壞的，第二版已避開（見下面）。

## 改法

### 1. 黑畫面時先接上、先編、先傳（`patches/zone_prewarm.diff`，第五版只在電腦上做）

- `src/zones3d.js` 新增 `Z3.prewarm(E,{cap})`：
  1. 等一個 macrotask，讓已載過的正式模型接上；
  2. `renderer.compileAsync` 編場景的材質（有 `KHR_parallel_shader_compile` 時不卡主執行緒、多個 shader 同時編）；
  3. 把貼圖傳上 GPU，每約 400 萬像素讓出一次主執行緒；
  4. 最多等 `cap`（2 秒），超過就照原本的方式（剩下的第一格做）。
- **只做看得到的物件**（`traverseVisible`）：被正式模型取代、藏起來的套件備用模型不編、不傳（省時間也省 GPU 記憶體）。`compileAsync` 自己會走到藏起來的物件，所以同步編譯那一步先把它們的 material 暫時拿掉、編完馬上放回去。
- `src/game3d.js`（**LAWWW 的檔，一行**）：`enter()` 在 `E.update` 之後、`E.render` 之前、淡入之前 `await Z3.prewarm(E,{cap:2000})`；`noFade`（搭電梯換區域）不等。
- 代價：黑畫面多停一下（在電腦上應該是零點幾秒；SwiftShader 的數字見下面），換來淡入時畫面不停。

### 2. 電腦上預先載下一個區域的建築模型（同一個 patch）

- `Z3.prefetchNext`：prewarm 做完 4 秒後，照表把下一個區域的建築模型一個一個 `ASSETS.loadOne`：公館 → 溫州街六個、溫州街 → 咖啡廳室內、咖啡廳 → 溫州街。
- 一次一個、中間空 1.5 秒、已經載過的跳過、換了區域就停。
- **只在電腦上做**（`ASSETS.texCap` 是空的＝不是手機）：手機記憶體少，照舊進去才載。網址 `?noprefetch` 關掉，`?prefetch` 手機模擬也做（量測用）。

### 3. 日式宿舍不再帶整張圖集（`63d3bc5e`）

- `tools/blender/env_second/wz_jphouse.py` 從招牌圖集切出燈籠、木牌那一塊（288×416，邊界對齊 32 像素，前五層 mipmap 和原圖集同一塊相同），UV 換成小圖座標。
- 其他網格的頂點資料和原本完全相同；兩個網格的 UV 對到原圖集的像素位置差 < 0.0001 像素。`wz_jphouse.glb` 939,908 → 668,576 bytes。

## 給 LAWWW 的建議：路人底模池（不在這個 patch 裡）

現在 `C.anonPool.refresh` 每次換區域把 8 個路人底模全部換新（使用者 10-17「長得很像的路人太多」），`GM.upgradeModels` 等到新的 VRM 到了，**同一格一起換上**。上面的量測：這是換區域以後最大的一次卡。建議（任選、可以合用）：

1. **每次換區域只換 2 個**（8 個裡輪替 2 個），其他 6 個留著：走三四個區域就全部換過一輪，長相照樣會變，但一次只多 2 個新模型。
2. **`upgradeModels` 一次只換一個**（每 1.5 秒一個），不要同一格全部換：卡頓分散成幾個小的。
3. **換上之前先編**：新的 VRM 到了，先 `renderer.compileAsync(vrm.scene, camera)`（或放到看不到的地方畫一格），編好再換上。
4. 數字：路人不輪換時，「咖啡廳 → 溫州街（第二次）」最長一格 8.5 → 4.2 秒、多出來的時間 5.9 → 2.1 秒（SwiftShader）。
