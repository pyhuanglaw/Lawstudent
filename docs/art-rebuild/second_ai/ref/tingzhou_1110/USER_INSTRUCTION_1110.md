## 第一則（附七張圖：三張公館地圖、四張街景照片；圖的用途見 REF_ANALYSIS.md）

這次要做的是「汀州路商圈」而不是 generic 台北街景。請以台大公館商圈為基礎，重點抓學生生活圈的氣質。

參考方向：

1. 主街是台北舊式中低樓層街屋，一樓店面密集，二樓以上有老公寓感、鐵窗、招牌。
2. 店型要混合：平價小吃、飲料店、咖啡店、運動用品、手機通訊、日常生活店。
3. 汀州路要有「東南亞美食街」特徵，混入泰式、馬來西亞、印尼、緬甸等餐館外觀。
4. 優先做傍晚到夜間版本，店招亮起、人潮增加，但仍保留日常通行的街道感。
5. 水源市場附近要有較高的人流感。
6. 不要做成觀光夜市，不要做成西門町步行街，也不要做成高級新商圈。
7. 整體關鍵字是：台大學生、平價、日常、混合店種、東南亞美食、人文咖啡、傍晚熱鬧。

## 第二則

LAWWW2｜汀州路商圈 3D 美術製作指令

請針對《Lawstudent／法條之外》的汀州路商圈進行高品質 3D 美術製作。

這次希望充分利用 Claude Fable 5.2 的視覺理解、空間推理及程式開發能力，而不是只透過文字想像場景。

一、先研究視覺參考

請先查找並分析台北公館汀州路三段的真實街景，優先使用街景照片、街景地圖，以及使用者提供的 2D 參考圖。

將參考圖片區分為：

1. 街道整體構圖與建築高度
2. 騎樓、店面、招牌、遮雨棚
3. 東南亞餐館及日常生活店家
4. 白天與夜間的光線
5. 街道上的生活細節

每張圖片都要明確記錄用來參考什麼。不要將不同照片的建築位置誤認成同一條街。

如果有使用者提供的 2D 目標圖，以該圖作為主要視覺目標。真實街景用來補充未呈現的結構與生活細節。

二、目標美術風格

這是一款以台灣大學生活為背景的 3D 校園生活 RPG。

汀州路商圈應該呈現：

* 具有台灣特色的中低樓層街屋
* 一樓密集店面與騎樓
* 二樓以上的住宅、窗型冷氣、鐵窗及陽台
* 新舊混合的招牌、門窗及建築材質
* 平價餐館、日常服務店、學生常去的小店
* 機車、道路標線、盆栽、電箱、排水孔等生活細節
* 傍晚及夜間具有層次的商店燈光

不要把整條街變成統一規格的方盒子店面。

每間店的門面寬度、深度、招牌位置、燈光和裝修年代可以不同，讓整條街自然地呈現長期發展形成的樣貌。

視覺品質以精緻的半寫實遊戲場景為目標，避免塑膠感、重複貼圖和空蕩蕩的建築外觀。

三、既定店家與世界觀

請先核對 GitHub 最新規則、使用者指示及商圈配置，保留現有公館區與汀州路的連接方式。

目前已確定要放在汀州路商圈的店家包括：

* 泰米村食：泰式料理餐館，應能從店面看出餐飲特色
* 洗樂洗衣坊：台灣自助洗衣店
* 印得好：學生常用的影印輸出店

其他已決定的店家，包括安泰藥局、汀州鮮果、榮恩典文具社，應先核對已確認的位置，不要擅自重新分配。

不要覆蓋既有地點、改動使用者已確認的店名，或因美術重建破壞已完成的遊戲系統。

四、使用 2D 到 3D 的工作方法

沿用專案既有的 RULES_2D_TO_3D.md 與同角度疊圖流程。

1. 解析參考圖的建築輪廓、地面透視、前後景及店家排列。
2. 反推參考圖的相機位置、方向、焦距與主要比例。
3. 在 Blender 先建立正確的街道、建築和店面配置。
4. 建立材質、招牌、騎樓及細節。
5. 使用參考圖對應鏡頭輸出 3D 截圖。
6. 將參考圖與 3D 截圖疊圖比對，檢查構圖、輪廓、比例及主要物件位置。
7. 完成後再檢查玩家正常遊玩視角，而不只檢查單張宣傳構圖。

不能以「Blender 成功輸出模型」當成美術完成的證據。

五、美術驗收

交付時至少提供：

* 商圈主街白天視角
* 相同位置的傍晚或夜間視角
* 玩家高度的街道行走視角
* 重要店家正面與斜角畫面
* 參考圖和 3D 實際截圖的並排對照
* 模型效能及遊戲可用性檢查

由實際截圖判斷是否改善，不只依靠程式測試 PASS。

優先改善整條街的比例、建築多樣性、材質及光線品質。

六、效能與交付原則

保持既有 Three.js、Blender 和 GLB 工作流程。

優先使用可重複利用的建築構件、模組化騎樓、適當的貼圖及 LOD，避免不必要的高面數模型。

遵守專案現有的「場景最多三版先進遊戲」規則。第一版先完成可走動、可辨識且有基本美術品質的街區，再集中改善真正影響觀感的地方。

不要為了微小差異無限重做，讓玩家一直玩不到新商圈。

LAWWW2 依既有權限製作與交件，由 LAWWW 負責整合；不要自行發布。

七、最重要的品質原則

目標不是做出一條「看起來像 AI 生成的台灣街道」，而是讓玩家一走進去，就感覺這裡真的有大學生生活。

應該有視覺上的不規則性、建築年代差異、不同店家的經營氣質，以及令人願意探索的街道細節。

最重要的是：以參考圖決定畫面，以 Blender 建立空間，以實際遊戲截圖驗證成果。

請先確認現有工程的進度及可沿用資產，不要把已完成的部分重新製作。

## 第四則（2026-11-10 19:3x UTC，對 LAWWW2；夜市攤位與道路）

你根據我提供的真實公館商圈照片與地圖，主動安排夜市攤位，這個方向很好，請保留。

但要注意：

1. 汀州路應該是一條有車流、機車、行人、固定店面及部分夜市攤位共存的真實城市道路，不是整條封閉的觀光夜市。
2. 請特別參考照片裡密集的直式招牌、老公寓、鐵窗、冷氣室外機、騎樓與不規則建築立面。這些對還原公館街景非常重要。
3. 夜市攤位請設計成可依遊戲時間出現、營業、收攤的模組化物件，不要永久佔據道路。
4. 夜市攤位需要有種類差異，例如麵煎餅、炸物、飲料、烤物、小吃，但不必每個攤位都能互動。
5. 請依照既有地圖與參考資料規劃攤位區域，不要把所有固定店家的門口全部堵住。
6. 先沿用已完成的商圈建設，優先檢查視覺品質、街道比例及玩家行走體驗，不要不必要地重新製作。

重點是讓玩家感覺這條街真的有人生活，而不是一排整齊的 3D 商店模型。

### LAWWW2 的做法（照這一則）
- 汀州路主街：車道照常（雙向兩線、路邊機車格）；**攤位不擺在主街車道上**。攤位區：巷 A（公館過來的小巷）兩側、主街幾個騎樓柱邊和巷口轉角、水源市場門口——每一攤都避開固定店家的門（配置裡每間店的 door_x ±1 m 不放攤）。
- 攤位＝獨立的小 GLB 模組（`STALL_<種類>_open`／`_closed` 兩種狀態：營業、白天蓋帆布或不在），位置寫在 `tingzhou_layout.js` 的 `stalls`；遊戲照時間（17:00 擺、24:00 收；颱風大雨不擺）切換，導航阻擋只在擺出來的時候算。
- 種類至少五種：麵煎餅、炸物、飲料、烤物、小吃（割包／蔥油餅）；只有一部分能互動（LAWWW 接「看」「買」）。
- 車流：遊戲目前沒有會動的汽車；主街做停著的車、路邊機車、公車站牌，會動的車要不要做由 LAWWW 評估（玩家可以走在路上，要有不撞人的做法）。
- 不重做：沿用已完成的配置 v3、wz_street --set tingzhou、招牌圖集；下一步先出圖檢查比例、立面密度（直式招牌、鐵窗、冷氣）、行走。
