【《法條之外：台灣法律人生》
Hybrid 3D Exploration × 2D Visual Novel Character System
正式設計規格】

這是一項新的長期核心架構要求。

IMPORTANT：

不要停止目前正在進行的開發。
不要重寫目前已完成的 gameplay systems。
不要為了這項要求推翻現有專案。

請把以下內容納入目前架構以及後續開發方向。

核心原則：

3D = WORLD / EXPLORATION / SPATIAL LIFE
2D = CHARACTER / DIALOGUE / DRAMA / EMOTION
CG = MAJOR STORY MOMENTS

《法條之外》不是純3D RPG，也不是純Visual Novel。

它是一款：

「3D校園生活RPG
＋
2D日系ADV人物演出
＋
法律人生養成」

的Hybrid Game。

━━━━━━━━━━━━━━━━━━━━━━
一、最重要：不要用程式碼畫動漫人物
━━━━━━━━━━━━━━━━━━━━━━

DO NOT：

使用CSS幾何圖形畫人物。
使用circle / triangle / rectangle拼人物。
使用SVG primitive自行拼動漫臉。
使用Three.js primitive製作2D角色。
使用Canvas程序化畫動漫人物。
把placeholder人物稍微改色後稱為正式立繪。

不要花大量時間自行「畫」正式角色。

正式2D角色未來會由外部高品質image assets提供。

你的工作是：

建立可以載入、管理、切換、演出這些圖片的系統。

如果目前沒有正式圖片：

使用明確標記的 placeholder image。

例如：

PLACEHOLDER_YUNA_NEUTRAL
PLACEHOLDER_YUNA_SMILE

甚至可以只用：

人物名稱＋輪廓＋表情名稱

但必須明確標記：

PLACEHOLDER_2D_PORTRAIT

不要試圖把placeholder加工成正式美術。

━━━━━━━━━━━━━━━━━━━━━━
二、3D與2D的工作分工
━━━━━━━━━━━━━━━━━━━━━━

3D MODE：

玩家自由探索世界。

包含：

校園
椰林大道
系館
教室
圖書館
宿舍
咖啡廳
餐廳

玩家可以：

walking

entering buildings
finding NPCs
seeing NPC activities
interacting with objects
checking schedule
going to class
studying

3D的核心價值是：

「空間存在感。」

玩家應該覺得：

我今天真的從宿舍走到系館，
上完課去了圖書館，
晚上又去了咖啡廳。

四、ADV MODE畫面
━━━━━━━━━━━━━━━━━━━━━━

建立一套正式：

ADVSceneManager

BACKGROUND
CHARACTER SPRITE
DIALOGUE BOX
CHARACTER NAME
TEXT
CHOICES
OPTIONAL SECOND CHARACTER
EXPRESSION
TRANSITION
EVENT CG

手機優先。

角色立繪應占畫面主要視覺位置。

對話框位於畫面下方。

不要讓UI遮住人物臉。

支援：

tap to continue
choice selection
text reveal
skip
auto
dialogue history

如果時間不足：

優先完成：

dialogue
choice
sprite
expression
transition

其他功能可以之後做。

━━━━━━━━━━━━━━━━━━━━━━
五、背景呈現方式
━━━━━━━━━━━━━━━━━━━━━━

ADV MODE支援至少三種背景：

MODE A
Freeze current 3D scene

3D畫面停止玩家控制，
作為對話背景。

MODE B
Blur / darken current 3D scene

讓人物立繪更突出。

MODE C
Dedicated 2D background

例如：

classroom_day.webp
classroom_evening.webp
library_night.webp
cafe_rain.webp
dorm_night.webp
campus_sunset.webp

event可以指定使用哪一種。

━━━━━━━━━━━━━━━━━━━━━━
六、建立正式 Character Portrait Asset System
━━━━━━━━━━━━━━━━━━━━━━

不要把圖片路徑散落在dialogue code裡。

建立：

CharacterPortraitRegistry

概念例如：

characterId
displayName
defaultPortrait
outfits
expressions
variants

例如：

characterId: heroine_01

outfits:
  campus
  casual
  formal

expressions:
  neutral
  smile
  laugh
  surprised
  embarrassed
  annoyed
  sad
  serious
  tired
  thinking

每一個：

OUTFIT × EXPRESSION

不一定都需要獨立圖片。

系統應允許fallback。

例如：

如果：

campus_embarrassed.webp

不存在，

可以fallback：

campus_neutral.webp

不能crash。

━━━━━━━━━━━━━━━━━━━━━━
七、角色圖片格式
━━━━━━━━━━━━━━━━━━━━━━

正式人物圖片預計使用：

PNG
或
WebP

透明背景。

系統必須可以：

保持aspect ratio
依viewport縮放
適應手機直向／橫向
避免人物被拉伸
避免頭被裁掉
避免人物超出safe area

圖片資產與程式碼完全分離。

未來換圖片：

不應該需要修改dialogue engine。

━━━━━━━━━━━━━━━━━━━━━━
八、人物表情系統
━━━━━━━━━━━━━━━━━━━━━━

Dialogue line可以指定：

speaker
expression
outfit
pose
position

例如概念：

{
 speaker: "heroine_01",
 expression: "embarrassed",
 outfit: "campus",
 position: "right",
 text: "你剛剛是不是故意不看我？"
}

下一句：

{
 speaker: "player",
 text: "我只是在想明天的案例。"
}

下一句：

{
 speaker: "heroine_01",
 expression: "annoyed",
 text: "……最好是。"
}

切換expression時：

不要整個畫面閃白。

可以使用：

crossfade
短fade
或instant switch

依效能決定。

━━━━━━━━━━━━━━━━━━━━━━
九、支援兩人對話
━━━━━━━━━━━━━━━━━━━━━━

ADV MODE至少預留：

LEFT CHARACTER
RIGHT CHARACTER

兩人可以同時存在。

目前說話的人：

brightness / opacity = normal

沒有說話的人：

稍微降低brightness或opacity。

例如：

LEFT：
熟同學

RIGHT：
女主角

對話：

同學：
「你們兩個昨天是不是一起念到很晚？」

女主角：
「……只是剛好而已。」

玩家：
「你不要亂講。」

角色表情依序改變。

━━━━━━━━━━━━━━━━━━━━━━
十、玩家角色
━━━━━━━━━━━━━━━━━━━━━━

玩家自己通常不需要顯示完整立繪。

可以採：

第一人稱Visual Novel convention。

也就是：

NPC在畫面中，
玩家透過dialogue options說話。

但架構保留：

PLAYER PORTRAIT

未來如果需要：

鏡子
照片
CG
角色資訊
特殊事件

仍可使用。

━━━━━━━━━━━━━━━━━━━━━━
十一、NPC視覺分級
━━━━━━━━━━━━━━━━━━━━━━

不是所有NPC都需要昂貴立繪。

VISUAL_TIER

只有3D模型。

例如：

校園路人
圖書館學生
路上騎車的人

沒有正式portrait。

──────────

TIER 1 — ACQUAINTANCE

可以有：

簡單portrait / bust portrait

例如：

不熟的系上同學
通識課同學
偶爾遇到的人

表情數量少。

──────────

TIER 2 — RECURRING CHARACTER

完整人物立繪。

例如：

熟同學
室友
學長姐
重要研究生
重要助教

至少：

neutral
smile
annoyed
surprised
sad
thinking

──────────

TIER 3 — CORE CHARACTER

最高品質。

包含：

五位主要女主角
極重要NPC

具有：

多套服裝
大量表情
特殊姿勢
event CG
完整story arc

十三、不要做五種動漫模板
━━━━━━━━━━━━━━━━━━━━━━

禁止：

━━━━━━━━━━━━━━━━━━━━━━
十四、五人的科系不必全部法律系
━━━━━━━━━━━━━━━━━━━━━━

例如可以包含：

法律系

文學院
商管
理工／醫學相關
通識課認識的人

例如：

同系

社團
宿舍附近

這會讓五條人物線代表五種不同的大學生活。

━━━━━━━━━━━━━━━━━━━━━━
十五、角色第一次出現不要自帶攻略標誌
━━━━━━━━━━━━━━━━━━━━━━

禁止：

「女主角登場！」

禁止：

粉紅愛心UI。

禁止：

第一次見面就讓玩家知道這是可攻略角色。

第一次可能只是：

坐你旁邊的人
借你筆的人
一起分組的人
朋友帶來吃飯的人
圖書館碰到的人

玩家應該透過相處才逐漸意識到：

這個人對我的人生變重要了。

十六、角色立繪 Character Bible
━━━━━━━━━━━━━━━━━━━━━━

它是未來提供給image generator的設計規格。

十七、正式2D美術方向
━━━━━━━━━━━━━━━━━━━━━━

Contemporary Japanese visual novel / romance ADV inspired

不要模仿任何特定現役藝術家的風格。

建立自己的統一美術語言。

十八、台灣／台北的大學生感

━━━━━━━━━━━━━━━━━━━━━━
二十三、Choice System
━━━━━━━━━━━━━━━━━━━━━━

玩家選項不應永遠存在：

正確
普通
錯誤

不要讓玩家一眼看出：

哪一個是「女主角+5」。

選擇應代表：

個性
優先順序
生活方式
價值
時間分配

有時候沒有最佳答案。

例如：

朋友：
「要不要去吃宵夜？」

A：
「走啊。」

B：
「我明天要上台報告，下次。」

C：
「我晚點去找你們。」

三個都是合理人生選擇。

影響不同。

━━━━━━━━━━━━━━━━━━━━━━
二十四、Relationship不是單一數字
━━━━━━━━━━━━━━━━━━━━━━

FAMILIARITY

例如：

不代表：
