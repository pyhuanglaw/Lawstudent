# 《法條之外》永久 3D 美術製作規範

請將以下規則正式加入 GitHub 專案的 `CLAUDE.md`，並同步更新 `docs/art-rebuild/ART_DIRECTION.md`、`docs/PROJECT_DECISIONS.md` 及相關開發文件。

**這是長期有效的強制開發規則，不是單次美術修改建議。**

未來任何接手專案的 Claude Code 工作階段，都必須遵守。

## 一、最高原則：禁止回到廉價 3D 原型美術

《法條之外》的正式美術定位是：

**成人比例、日系青春生活模擬的細膩質感、具有台灣大學校園與台北都市辨識度的 3D 世界。**

遊戲應讓玩家感覺身處一個真實、完整、值得探索的生活環境。

禁止把以下方式當作正式美術的主要製作方法：

- 大量使用 `BoxGeometry`、`CylinderGeometry`、`SphereGeometry` 拼出完整建築、家具及人物。
- 用 Canvas 隨機繪製幾何斑點、色塊或線條，冒充精緻的石材、磚牆、木材與混凝土。
- 只靠增加幾何裝飾數量來宣稱美術品質提升。
- 把同一組模型換顏色，就當作不同重要角色或地標。
- 只改顏色、亮度、霧氣與陰影，就宣稱完成全面美術翻新。
- 以獨立模型預覽圖代替正式遊戲畫面驗收。
- 將測試通過視為美術品質達標。

這些方法仍可用於碰撞體、導航、遠景、效能最佳化、不可見輔助物件與開發階段的 blockout。

**正式近景美術必須以品質為準，不能再以最容易寫程式的方式取代真正的模型製作。**

## 二、每類美術資產的指定工具

| 資產類別 | 主要製作工具 | 正式成果 |
|---|---|---|
| 校園主要建築 | Blender bpy | 結構完整的 GLB 建築 |
| 樓梯、穿堂、走廊、電梯 | Blender + Three.js | 可實際行走、探索的空間 |
| 室內與家具 | Blender bpy | 有合理比例與材質的模型 |
| 台北公寓、騎樓、店面 | Blender + 模組化建築組件 | 具有台灣城市特色的街景 |
| 紅磚、石材、木材、柏油 | Poly Haven PBR + Blender | Base Color、Normal、Roughness 等材質 |
| 主角與重要 NPC | Blender + VRM / three-vrm | 有獨特外觀及完整動作的角色 |
| 人物動作 | Blender Animation + 現有骨架系統 | 行走、上下樓、坐下、互動 |
| 樹木、機車、腳踏車 | Blender + Three.js Instancing | 近景精緻、遠景輕量 |
| 天空、天氣與光線 | Three.js + 合法 HDRI | 隨時間變化的環境 |
| 模型與貼圖壓縮 | glTF Transform、Meshopt、KTX2 | 手機可流暢載入的最佳化資產 |
| 視覺與遊玩測試 | Playwright + Blender Render | 實際畫面、互動測試與新舊比較 |

指定的是工具用途與品質流程，不代表每項資產都必須使用全部工具。若已有品質更好、授權合法的正式模型，可以直接使用。

## 三、Blender 優先規則

所有重要建築、近景店面、主要室內家具與需要精細造型的物件，原則上優先使用 Blender 製作。

標準流程：

1. 蒐集或讀取現有參考照片。
2. 確認比例、尺寸、構造與辨識特徵。
3. 使用 Blender Python `bpy` 建模。
4. 使用合理的 PBR 材質。
5. 必要時 UV 展開與烘焙貼圖。
6. 匯出 GLB。
7. 整合進現有 Three.js 世界。
8. 驗證導航、碰撞、互動與樓層。
9. 壓縮與最佳化。
10. 提供實際遊戲截圖供使用者驗收。

**Blender 模型完成，不等於遊戲美術完成。**

只有在正式遊戲中正確顯示、可正常互動，且畫面符合品質目標後，才有資格進入最終驗收。

## 四、禁止製作不能探索的假建築

主要可進入建築必須支援真正的空間探索。

包括：
- 玩家可以進入大廳及穿堂。
- 可以走上樓梯與平台。
- 可以在不同樓層移動。
- 可以搭乘電梯。
- 可以進入開放的教室、圖書館及其他房間。
- NPC 可以在不同樓層活動。
- 鏡頭、碰撞、尋路和人物動畫正確配合。
- 玩家可以正常離開，不會永久卡住。

目前 D26 的平面高度限制，不應再作為正式設計的永久限制。

允許分階段完成樓層，但不能以不可行走的裝飾樓梯冒充完成。

Blender 負責視覺與必要的碰撞幾何；Three.js 的移動、導航和互動系統負責實際可玩性。

## 五、人物美術品質規則

主角與重要 NPC 必須具有：

- 成人比例，約 7–8 頭身。
- 各自獨特的五官、髮型與服裝。
- 自然的人體比例和衣物輪廓。
- 與角色個性及背景一致的外觀。
- 可靠的走路、跑步、轉身、坐下、上下樓梯等動作。
- 不穿模、不滑步、不漂浮。

VRoid 樣本可以作為製作基礎，但不能因為技術上可載入，就被視為最終角色模型。

優先改善臉型、髮型、衣服輪廓及動作，而不是只修改色彩。

## 六、材質品質規則

正式近景材質應優先使用合理的 PBR 工作流程。

優先使用已能取得且授權明確的 Poly Haven 資產。

需要依材質特性適當使用：

- Base Color
- Normal
- Roughness
- Metallic
- Ambient Occlusion

不要求每一種材質都有完整五張貼圖；重點是物理表現、模型細節與整體風格。

需要特別注意：
- 紅磚必須有自然排列、接縫與表面細節。
- 混凝土與花崗石不能只是單色平面。
- 木材需有適當紋理與粗糙度。
- 玻璃要有合理透明度與反射。
- 金屬欄杆與扶手應有自然光澤。
- 柏油路保持使用者指定的淺灰色，而不是擅自改成深黑色。

不得為了追求真實感而破壞遊戲整體美術風格或手機效能。

## 七、原有程式資產的處理規則

`src/campuskit3d.js`、`src/townkit3d.js`、`src/world3d.js` 中的程序化模型，不必全部刪除。

應將其分類為：

1. 已達品質要求，可以保留。
2. 適合遠景或背景，可以保留。
3. 適合作為碰撞、導航或 GLB 載入失敗時的備用。
4. 主要近景模型，必須升級。
5. 已由正式 GLB 取代，停止作為預設視覺資產。

逐項建立資產清單，明確記錄替換狀態。

不要重寫整個遊戲引擎，也不要破壞劇情、人物資料與玩家存檔。

## 八、永久視覺驗收制度

每次重大美術修改必須提交：

1. 真實照片或既有美術參考。
2. 修改前遊戲截圖。
3. 修改後遊戲截圖。
4. 相同角度、相近時間與光線條件的比較。
5. Blender 模型渲染圖。
6. GLB 模型與貼圖規格。
7. 手機模擬測試結果。
8. 實機尚未驗證的事項。
9. Git commit SHA。
10. 尚未達到參考品質的缺點。

禁止只用文字敘述「現在比較精緻」「材質改善」「細節增加」。

必須讓使用者實際看到差異。

驗收狀態分為：

- `BLOCKOUT`：原型或佔位資產。
- `MODEL_READY`：模型已製作。
- `INTEGRATED`：已整合正式遊戲。
- `FUNCTIONAL_VERIFIED`：相關互動已完成測試。
- `READY_FOR_ART_REVIEW`：等待使用者審核美術。
- `ART_APPROVED`：使用者明確接受美術品質。

只有使用者實際確認後，才能標記 `ART_APPROVED`。

## 九、不能用效能當作粗糙美術的預設理由

目標是**精緻而有效率**，而不是在精緻與效能之間只能選一個。

請優先採用：

- 可重用模型與材質。
- Instancing。
- LOD。
- 貼圖壓縮。
- 幾何最佳化。
- 適當的資產分區載入。
- 遠景簡化。
- 合理的光影品質分級。

主要人物、關鍵建築與玩家常停留的近景，是美術品質的優先保障區域。

不能在尚未量測實際效能之前，直接以手機效能為由，將主要人物或建築退回廉價方塊模型。

## 十、規則執行與交接

請將本規範寫入 `CLAUDE.md` 的高優先級規則，建立明確標題：

**MANDATORY 3D ART PRODUCTION RULES**

並將詳細流程放入 `docs/art-rebuild/ART_DIRECTION.md`。

在 `docs/PROJECT_DECISIONS.md` 加入新的永久決策，註明這套正式美術工具鏈優先於過去的程序化原型製作方式。

以後任何新增建築、室內、人物與街景，開工前都必須先判斷適合的製作工具，不得自行退回舊的低品質程序化方法。

每次開發回報，必須寫明實際使用的建模工具、材質來源、整合情況與驗收狀態。

**目前劇情、角色設定、法律內容全部暫停修改，優先完成美術與多樓層探索系統。**

將規則寫入並提交 GitHub 後，繼續執行目前已經授權的美術升級，不要只更新文件就停止施工。
