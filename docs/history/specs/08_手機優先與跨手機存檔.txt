對，**改成手機優先，存檔能匯出成檔案，再到另一支手機匯入接著玩**。這段直接補給它，取代前面以桌機、Steam 為優先的要求：

【開發方向更新：手機優先＋跨手機存檔】

本段優先於前面衝突的要求。請以「手機遊戲」為主要開發目標，桌機與 Steam 作為未來延伸。保留原本的美術、校園生活、人物關係與完整可玩要求。

一、手機操作與畫面

- 以橫向遊玩的手機遊戲設計場景與介面；直向開啟時顯示清楚的旋轉提示，不假設瀏覽器一定允許強制轉向。
- 支援 iPhone Safari 與 Android Chrome，優先交付可直接用網址開啟的版本。
- 使用點擊移動，另提供可開關的虛擬搖桿；互動按鈕放在拇指方便觸及的位置。
- 所有功能都能以觸控完成，不依賴鍵盤、滑鼠右鍵或游標懸停。
- 按鈕觸控範圍至少約 44～48 CSS px，文字在手機上不需放大即可閱讀。
- 適應瀏海、安全區域與不同螢幕比例，對話框不得遮住重要操作。
- 避免誤觸、頁面意外捲動及拖曳時觸發瀏覽器手勢。
- 手機切到背景時暫停遊戲，回來後能安全繼續，不因切換通訊軟體錯過事件。
- 控制動畫、素材大小與特效負擔，讓一般手機也能流暢遊玩。

二、完整存檔系統

必須提供：
1. 自動存檔。
2. 至少三個手動存檔欄位。
3. 匯出存檔。
4. 匯入存檔。
5. 載入前備份與錯誤復原。

在重要事件、完成活動及切換場景時存檔，不要只依賴關閉頁面時才保存。

存檔必須包含所有影響後續遊戲的資料：
- 角色設定、日期、章節與所在位置。
- 能力、金錢、物品、服裝及房間布置。
- 課業、筆記、考試與任務進度。
- NPC 關係、已觸發事件、重要選擇與後續事件條件。
- 交換、實習和職涯進度。
- 其他維持遊戲連續性所需的狀態。

三、跨手機匯出與匯入

玩家在手機 A 選擇「匯出存檔」，取得一個包含完整進度的 JSON 存檔檔案，可以透過手機檔案功能、通訊軟體或雲端硬碟傳到手機 B。

手機 B 開啟同一款遊戲，選擇「匯入存檔」，從檔案選取器選擇該檔案，即可延續遊玩。

- 匯出的是真正的存檔檔案，不能只是顯示一段文字。
- 檔名包含遊戲名稱與匯出日期，方便辨識。
- 環境支援檔案分享時，可提供系統分享功能；不支援時保留下載方式。
- 匯入前顯示角色名、遊戲日期、章節、遊玩時間與存檔版本。
- 玩家確認後才寫入指定欄位，預設不覆蓋現有進度。
- 若要覆蓋，先保留原存檔備份。
- 匯入後立即保存到新手機，重新整理或重開遊戲後仍可繼續。

不要求登入，也不需要付費服務。本次先完成可靠的手動跨裝置移轉；介面要清楚說明「換手機前先匯出」，不要把本機自動存檔稱為雲端同步。

四、存檔驗證與版本相容

- 存檔包含遊戲識別碼、資料格式版本、遊戲版本與儲存時間。
- 匯入時驗證檔案大小、欄位、資料型別及合理範圍，不執行檔案內任何程式碼。
- 損壞、錯誤遊戲或不相容的存檔要顯示明確訊息，不能破壞既有存檔。
- 後續更新遊戲時提供舊存檔遷移機制。
- 若無法支援較新版本存檔，清楚提示，不要勉強載入造成資料遺失。
- 存檔不包含秘密金鑰或不必要的個人資料。

五、手機驗收

必須測試以下完整流程：
手機尺寸環境 A 建立角色並遊玩 → 匯出 → 獨立環境 B 匯入 → 確認人物關係、物品與事件進度一致 → 繼續遊玩 → 重開後仍能讀取。

另測試取消匯入、匯入損壞檔案、覆蓋備份，以及更新版本後讀取舊存檔。

請區分「實際手機測試」與「桌機模擬手機尺寸測試」，如實交代驗證範圍。

我醒來後最重要的使用情境是：拿起手機就能玩，玩到一半可以保存，換另一支手機後能從相同進度繼續。請把這個流程當成必要交付條件。
